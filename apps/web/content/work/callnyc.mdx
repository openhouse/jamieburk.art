## Context

CallNYC.org was a public-facing civic-data prototype. The practical problem was simple to state and difficult to make usable: a resident may know an issue or address, but not know who represents them, who to call, or what the next useful action is.

## What I did

- Structured public civic data into a resident-facing tool.
- Worked on information architecture for practical guidance.
- Framed the project as a prototype rather than an official service.
- Preserved the line between public usefulness and current official authority.

## How people used it

The prototype helped explain how civic data could become a clearer action path for residents. It also became proof of the implementation pattern: turn a public dataset and confusing decision path into a more usable public interface.

## Outcome / evidence

The project remains framed as archived. It is valuable as proof of civic-data translation, public-facing tool design, and prototype implementation. It is not presented as a current service.

## Transferable proof

This case supports technical project management, civic technology, and implementation roles because it shows the ability to turn ambiguous public information into a concrete interface with careful claim discipline.
