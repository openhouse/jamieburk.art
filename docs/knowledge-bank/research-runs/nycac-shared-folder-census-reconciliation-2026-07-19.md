# NYC Artist Coalition Shared-Folder Census Reconciliation

## Decision

No single shared-folder population total is canonical at present. The five
frozen branches report different totals from authenticated archival-production
passes:

| Frozen branch | Reported accessible items | Current interpretation |
| --- | ---: | --- |
| `feature/knowledge-wiki-A` | 2,365 | Valid as A's July capture under its descendant-counting method; not cross-capture canonical |
| `feature/knowledge-wiki-B` | 2,408 | Valid as B's unique-accessible-item observation under its method; not cross-capture canonical |
| `feature/knowledge-wiki-C` | 2,078 | Method-bounded observation requiring manifest comparison |
| `feature/knowledge-wiki-D` | 2,192 | Method-bounded observation requiring manifest comparison |
| `feature/knowledge-wiki-E` | 2,405 | Method-bounded observation requiring manifest comparison |

The spread is evidence about the retrieval process, not permission to choose a
convenient number. The canonical total is held, and no portfolio surface should
project one of these values as the archive's settled size.

## What remains supported

Each pass can still support bounded findings from documents that were actually
read, provided the source, attribution, rights, and claim boundaries are
independently sound. A disagreement about collection population does not erase
a verified checklist, public campaign artifact, or carefully limited source
reading. It does prevent the population total from serving as an authority cue.

## Reconciliation method

A future private pass should:

1. bind each protected manifest to capture time, account, retrieval surface,
   and traversal code or procedure;
2. normalize item identity, shortcuts, duplicate parents, folders, files,
   trashed items, and limited-access placeholders;
3. compare item-ID sets rather than totals alone;
4. account for collection changes between captures;
5. rerun one declared method if the original receipts permit;
6. publish only the resulting aggregate and method boundary after Jamie
   reviews it.

## Public boundary

Do not publish private titles, item IDs, paths, participant data, file bodies,
or account details to resolve this question. `100%` may describe closure inside
one explicitly defined capture and method. It must not imply that a mutable
shared folder has one timeless, independently verified population.
