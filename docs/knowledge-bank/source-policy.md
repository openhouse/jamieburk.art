# Source Policy

This public repo can hold public-safe claim logic, but it must not hold the
private source archive.

## Public-Safe Support

Use these source classes for claims:

- Approved resume language.
- Public project artifacts, public websites, public records, public coverage,
  public repositories, and public URLs.
- Public-safe archive summaries that aggregate private evidence without exposing
  names, rows, paths, screenshots, transcripts, correspondence, credentials, or
  sensitive operating details.
- Jamie-reviewed firsthand context where the wording is careful and bounded.

## Projection Rule

The website may use strong claims when the claim has approved wording,
defensible evidence posture, and explicit guardrails in `claims.md` or
`apps/www/src/data/proofs.ts`.

For exact metrics, prefer approved wording plus careful contribution language.
If a claim is true but not ready for a public page, keep it out of the website or
use fallback wording.

## Do Not Publish Here

- Raw transcripts, repaired transcripts, Otter exports, or meeting excerpts.
- Private emails, private notes, strategy records, or legal-review materials.
- Customer, guest, resident, collaborator, vendor, or stakeholder lists.
- Private screenshots, dashboards, analytics exports, revenue detail, or
  financial records.
- API keys, credentials, private fonts, private archives, or unapproved assets.

## Human Review

AI-assisted summaries can help organize evidence, but public claims remain
human-reviewed. If a claim would be uncomfortable quoted without context in a
newspaper, it needs narrower wording or should stay private.
