# Source Policy

The Knowledge Bank may mention source classes. It must not contain protected
source contents.

Never commit private source files to the repo for the purpose of proving a
claim.

## Source Classes

### public-source

Public web pages, public records, public campaign pages, public press, public
repositories, and other materials already intended for public access.

Safe behavior: link when appropriate, but do not overstate what the public
source proves.

### public-artifact

Public-facing artifacts Jamie has approved for publication or description.

Safe behavior: cite or summarize the artifact. Do not infer private facts from
it.

### approved-resume

Claims present in the current approved resume PDF.

Safe behavior: use only the exact approved resume wording or narrower public
wording. The resume may include contact information that should not
automatically appear in HTML.

### public-safe-summary

A summary of protected or mixed source material that has been rewritten to avoid
private details, names, records, paths, screenshots, or quotes.

Safe behavior: use the summary as confidence and wording support. Do not commit
the protected source behind it.

### private-source-outside-repo

Protected source material that may inform confidence but must not be committed:
private emails, raw transcripts, private correspondence, private coalition
notes, legal-review materials, stakeholder lists, internal analytics,
client-private materials, raw community records, private screenshots,
unapproved quotes, unapproved photos, private fonts, credentials, and API keys.

Safe behavior: reference only the source class and public-safe summary.

### conversation-summary

A public-safe synthesis of a private or semi-private conversation.

Safe behavior: do not quote private calls, attribute private comments, or name
participants unless explicitly approved.

### approval-required

Material that may be true but needs Jamie or collaborator approval before public
projection.

Safe behavior: keep it in the Knowledge Bank as Pending, not on public app
pages.

### protected

Material or claim types that must stay outside public pages and outside the repo.

Safe behavior: record the boundary, not the source contents.

## Not Allowed In Repo

- private emails
- raw transcripts
- private correspondence
- private coalition notes
- legal-review materials
- stakeholder lists
- internal analytics
- client-private materials
- raw community records
- private screenshots
- unapproved quotes
- unapproved photos
- private font files
- credentials
- API keys
- local private paths

## Source Rules

- Public sources may be linked if appropriate.
- Approved resume claims may be used only if the exact resume PDF is approved.
- Public-safe summaries may be used without exposing protected evidence.
- Private source summaries may inform confidence but must not reveal source
  contents.
- Conversation summaries must not quote private calls unless explicitly
  approved.
- Do not paste private local file paths into source notes.
- Do not use source material to create new public obligations for collaborators
  who have not approved the publication.
