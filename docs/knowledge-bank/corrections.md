# Corrections

Material public wording changes should have correction records. The point is to
make review history durable without turning public pages into process notes.

Correction records should identify:

- what changed;
- prior wording when relevant;
- revised wording;
- why the change was made;
- effective date;
- reviewer when known;
- superseded claim or projection when relevant;
- whether the correction is applied or required before production.

Current CallNYC correction records:

- `callnyc-years-2014-2015-to-2016`
- `callnyc-first-civic-data-to-first-councilstat`
- `callnyc-future-source-link-replacement`
- `callnyc-future-photo-rights-status-change`

Required-before-production corrections fail `npm run check:citations`.
