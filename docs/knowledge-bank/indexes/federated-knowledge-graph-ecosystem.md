# Federated Knowledge Wiki graph ecosystem

## Central finding

The ecosystem's current leading edge is not a larger graph or a new shared
database. It is an **operational federation**: distinct systems increasingly
own distinct kinds of authority, and their interfaces are becoming explicit,
typed, bounded, and testable.

The strongest recent work separates seven responsibilities:

1. governed archival research and source custody;
2. subject-specific evidence and semantic synthesis;
3. bounded graph-radius packet materialization;
4. public-record orientation around a person and practice;
5. issue-specific canonical public source bodies;
6. project-specific public-experience candidates; and
7. selective portfolio projection.

That division matters more than repository count. It prevents one convenient
system from silently acquiring authority over private source access, factual
interpretation, collective credit, security, recipient selection, public
wording, deployment, and indexing at once.

This page records a time-bound close reading. Its structured claim and any
outward projection remain held. RFC 0005 remains `exploring`; this evidence
does not advance its stage or authorize implementation.

## What has changed

Earlier Knowledge Wiki work proved that a public-safe Markdown corpus could
compile into a typed graph, retain claims and counterclaims, and project a
selective website. The current ecosystem extends that model in five important
ways.

### Custody and interpretation are becoming different jobs

Governed research packages now preserve source coverage, claim ledgers,
artifact dispositions, checksums, privacy review, and handoff notes without
requiring the portfolio repository to absorb protected source bodies. The
portfolio can receive a public-safe observation and a boundary while the
research package remains responsible for source identity and custody.

### Graph traversal is becoming a recipient contract

The packet layer no longer treats every nearby evidence item as equally useful
context. It can freeze a semantic radius, attach evidence afterward, summarize
large deferred hubs by count and digest, apply explicit artifact budgets, and
compose the most restrictive boundary. Compact overviews and attributed lenses
make a packet easier to orient without inventing one total institutional voice.

This is a significant maturation: the graph becomes a way to negotiate the
size, audience, and authority of context rather than a justification for
maximum retrieval.

### Source editions are becoming canonical by purpose

The Jamie-centered public record now adds public-source routes into WOW List's
product leadership, social practice, and recomposable project logic. The
issue-specific public-support edition retains complete statement and policy
source bodies. The portfolio does not need to copy either edition wholesale.
It can import a bounded claim, source identity, correction state, and public-use
decision while leaving canonical bodies where their context is strongest.

### Protected subject knowledge is distinguishing preservation from release

The protected subject layer now separates bounded population receipts,
artifact lineage, repository preservation, security holds, collective credit,
and unresolved access. That is more exact than saying an archive has been
"saved." Preservation can be true while collaborator access, credential
clearance, present-day software safety, rights, consent, and publication remain
open.

### A public project threshold is becoming editorially governed

The current project candidate work uses historical tense, original public
artifacts, shared builder credit, a source-backed writer's-voice method, and a
human-reviewed copy register. It offers a bounded way back into a project
without claiming that the historic member service is live or that the archive
is complete.

The key contribution is not only visual restoration. It is the ability to bind
public copy to reviewed sources and an exact candidate while still reserving
literary judgment, member contact, rights, consent, deployment, and indexing
for people.

## Current authority map

| System role | Canonical for | Must not become |
| --- | --- | --- |
| Portfolio projection | Audience composition, public-safe claims in this repository, exact-candidate release evidence | A private archive, universal source of truth, or automatic publisher |
| Public-record edition | Public-source orientation, browse structures, corrections, coverage gaps | A private-source disclosure route or endorsement register |
| Issue-source edition | Complete issue-specific public source bodies, speaker and legislation indexes | A portfolio, causal account, or current-role oracle |
| Governed research production | Named research-package custody, ledgers, checksums, privacy review | A live synchronized backend or publication authority |
| Packet materializer | Semantic radius, recipient contract, artifact budget, boundary intersection | A truth engine, source adapter, or editorial approver |
| Protected subject knowledge | Bounded observations, source census, lineage, preservation and security state | Credential clearance, collaborator permission, or public wording authority |
| Project threshold | Project implementation, source-return decisions, candidate copy and interface checks | A full relaunch, archive browser, member-contact program, or release approval |

No role is subordinate merely because it is not public. No role becomes
canonical for another role merely because it can read its output.

## Governed handoff sequence

The common interface is:

```text
source custody
  -> bounded capture receipt
evidence and atomic observation
  -> interpretation and collective-credit review
semantic record
  -> recipient, purpose, radius, and artifact budget
bounded packet or source edition
  -> rights, consent, credit, editorial, and release gates
public project or portfolio projection
  -> dated capture as new evidence, never silent synchronization
```

Every arrow is non-automatic. The output of one system is an input proposal to
another system, not an inherited permission.

The machine-readable snapshot in
`config/knowledge-wiki/federated-ecosystem.snapshot.json` preserves the current
roles, handoffs, and invariants. Its evaluator fails if a protected locator is
made public, an RFC stage is advanced, a handoff becomes automatic, a projection
gate disappears, or a project threshold acquires relaunch authority.

## Close reading of the operating model

### The graph is a constitution before it is a convenience

The most important edges are not merely `related_to`. They name who may act,
what a record supports, which boundary follows it, whose contribution is
visible, and what is still held. A graph that cannot represent refusal,
correction, protected absence, contradiction, or withdrawal is too weak for
this archive even if its retrieval is fast.

### Heteroglossia is operational data

Attributed lenses and typed handoff states turn disagreement into maintainable
structure. `Communicated`, `received`, `incorporated`, and `acted` are different
events. A compact overview should preserve those differences rather than
inventing a collective voice or assuming that available knowledge shaped a
decision.

### Completeness is local

A source population can be complete at a frozen cutoff while the wider archive
remains incomplete. A Git history can be privately preserved while security
clearance remains open. A public project threshold can be compositionally
coherent while the historic platform is offline. Each completeness claim needs
its own population, date, receipt, and non-claim.

### Correction is the missing federation test

The ecosystem has strong local correction practices, but the next hard problem
is propagation. If a source edition corrects a role, date, credit, or
publication boundary, downstream packets and projections need a
content-addressed way to detect that change without becoming a live dependency.
The correct experiment is a bounded correction drill with rollback and human
review, not automatic synchronization.

### Usefulness remains a human question

Count-and-digest budgets and deterministic evals can prove that a packet is
bounded. They cannot prove that the chosen context is adequate for a hiring
reader, collaborator, researcher, editor, or community participant. Recipient
holdouts should judge orientation, missing context, burden, voice, and the
ability to contest or withdraw—not only structural validity.

## Why this branch is a leading edge

`feature/launch-2026-08-13-02-A` is the leading edge only in a precise sense:
it is the first portfolio launch-candidate line to record the ecosystem's
current specialization as a governed interface and bind it to a deterministic
authority contract.

It does not merge adjacent candidates, create adapters, expose protected
sources, add a database, publish a new site route, deploy staging, deploy
production, or enable indexing. Its value is constitutional: it makes the next
integration discussable and testable without pretending that integration has
already been authorized.

## Next questions

- Can every handoff emit a content-addressed public-safe receipt without
  exposing a protected locator?
- Can one correction propagation drill prove detection, review, rollback, and
  withdrawal without a live synchronization dependency?
- Do independent recipients find degree-bounded packets useful, plural, and
  appropriately incomplete?
- Which system owns withdrawal when consent, rights, security, or source
  authority changes?
- What minimum adapter contract could be prototyped read-only while RFC 0005
  remains `exploring`?

The answer to each question should preserve the current rule: access is not
consent, evidence is not publication permission, a graph relation is not
causation, a packet is not a projection, and an automated score is not human
approval.
