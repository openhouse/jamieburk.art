# Publishing Governance

## Rule

A claim moves from private context to public website only through the knowledge
bank.

## Flow

1. A source, memory, artifact, correction, or photo lead enters as an intake record.
2. Private material remains outside the repo; the intake stores only a public-safe summary and optional opaque locator.
3. A reviewer decomposes public sources into support and non-support boundaries.
4. Research inquiries preserve open questions and search limitations.
5. Mature claims receive evidence, guardrails, anti-claims, and projection intent.
6. Website projection uses only Ready or Careful claims selected for a named surface.
7. If a page needs stronger wording, update the bank first.
8. Public-safety checks fail production if pending/private/approval-marker
   material is projected.

## Status Meanings

- Ready: strong enough for public site copy.
- Careful: usable publicly only with the stated guardrail.
- Pending: do not use publicly until missing approval/citation is resolved.
- Private: source material exists, but the claim should not be published.

## Chad-Lens Review

Before a claim appears publicly, ask:

- Is Jamie visible as the actor?
- Does the claim answer "toward what end?"
- Is it legible to a hiring manager, public-sector reader, or HR reviewer?
- Does it name the specific work rather than hiding behind "data," "systems,"
  or "AI"?
- Does it use stewardship language where appropriate?
- Does it avoid inflated ownership claims?
