# Knowledge Bank

This folder is the public-safe source of truth for how the portfolio represents
Jamie Burkart's work. It is not a private archive, CMS, database, or evidence
dump. It is a governance layer for turning private source material, public
records, approved resume language, and project memory into bounded public
claims.

The site should answer one question quickly:

> Jamie creates operating structure for complex public-facing teams.

Plain-language version:

> Jamie turns ambiguous, loosely defined work into usable systems.

## What This Folder Answers

- Which claims are approved for public use?
- Which claims need Jamie approval or better source support?
- Which projects are public-safe summaries only?
- What language should the website use?
- What must never be published?
- How should future contributors decide whether a stronger claim is allowed?

## Operating Rule

Every claim should pass the newspaper test: if it would be awkward, unsafe, or
unfair to see quoted publicly, it does not belong in the public repo.

Use public-safe summaries, source categories, careful collective-work language,
and explicit boundaries. Do not include private paths, raw transcripts, private
correspondence, private coalition records, internal analytics, credentials,
client-private material, or unapproved screenshots, photos, quotes, names, phone
numbers, or font files.

## Projection Model

The knowledge bank can hold more nuance than the website shows:

- Homepage: only the strongest approved proof points.
- Resume page: approved highlights and public-safe role framing.
- Work pages: project-specific evidence plus Known / Open / Protected limits.
- Technical Operations page: role-specific evidence for hiring reviewers.
- Lab pages: bounded methods, not product pitches or private archive browsers.

When in doubt, keep the claim in `public-claims-inventory.md` as a candidate and
do not project it onto the website.
