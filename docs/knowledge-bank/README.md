# Knowledge Bank

This knowledge bank is the public-safe source layer for Jamie Burkart's
professional accomplishment claims. The website projects selected claims from
this bank for audience, clarity, and purpose.

The repository is public. Nothing here should be unsafe, unfair, private, or
context-collapsing if quoted in a newspaper.

## What This Is

- A public-safe claim ledger for professional positioning.
- A review aid for website, resume, and referral copy.
- A boundary system for separating known facts, open questions, and protected
  material.
- A way to make Jamie's role visible without overstating collective work.

## What This Is Not

- Not a raw archive.
- Not a transcript browser.
- Not a private evidence locker.
- Not a legal-review file.
- Not a public `/proofs` page.

## How To Use It

1. Start with `public-claims-inventory.md`.
2. Check `proofs-bank.md` for fuller context, claim boundaries, and project
   notes.
3. Check `source-classes.md` before relying on any source basis.
4. Apply `chad-lens.md` before projecting a claim onto the website.
5. If an approval is missing, record it in `approval-status.md` and use:
   `TODO: Jamie approval required.`

## Status Labels

- `approved`: ready for public copy when phrased as listed.
- `public-safe`: safe as public-safe summary, often with contribution language.
- `use-with-care`: usable only with the stated qualifier or boundary.
- `needs-jamie-review`: likely useful, but not for production copy yet.
- `hold-for-citation`: wait for exact public citation or source confirmation.
- `protected`: do not publish the claim, source, screenshot, quote, or detail.

## Projection Rule

The site should be clearer and shorter than the bank.

For hiring and referral readers, prefer role-fit claims: requirements,
workflow mapping, source maps, decision records, action tracking, launch
support, onboarding, public guidance, and durable handoffs.

For civic and coalition work, use collective language: helped, contributed,
co-built, supported, structured, stewarded, translated.

For archive-backed metrics, use aggregate numbers only when they clarify scale
and the public-safe inventory says the wording is usable.

## Public-Safety Rule

Do not publish private emails, raw transcripts, private coalition notes,
legal-review materials, health or financial details, private correspondence,
unapproved photos, credentials, private stakeholder lists, internal analytics,
client-private materials, raw community records, private source files, or
private local paths.

When a private archive supports a public claim, publish only the aggregate
claim or public-safe summary. The protected source material stays out of the
repo and out of the website.
