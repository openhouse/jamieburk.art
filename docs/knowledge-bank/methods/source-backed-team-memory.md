# Knowledge Wiki Graph / Source-Backed Team Memory

The Knowledge Wiki Graph is the current successor to Jamie's Noting.us and
Source-Backed Team Memory experiments. It turns scattered project records into
a system a future reader can inspect and continue. The method separates intake,
observation, claim, evidence, correction, projection, and protected absence.

## Three-graph architecture

1. The **semantic graph** describes what the work means: projects, actors,
   decisions, requirements, claims, corrections, and open questions.
2. The **evidence graph** records what supports, complicates, or contradicts an
   interpretation: sources, artifacts, observations, limits, and support types.
3. The **source-custody graph / layer** records where authoritative material
   lives, which exact version is in view, and which access, rights, retention,
   consent, and reuse conditions apply.

Audience-specific projection is a separate controlled output. A claim can be
well supported and still remain held from a public surface.

## Repository pattern

The ecosystem uses several independently useful repository roles:

- source-custody and archival-research projects preserve requests, materials,
  exact artifact pointers, manifests, and protected boundaries;
- subject editions organize canonical source bodies and campaign- or
  theme-specific statements;
- Jamie-centered public records preserve public-safe professional evidence;
- project Knowledge Wikis connect sources, observations, claims, contradictions,
  evals, corrections, and projections for a particular body of work;
- deterministic packet and evaluation tools materialize only the context a
  defined review needs; and
- the portfolio composes a small public argument from approved projections.

Stable identities can connect these instances, but no federation step merges
stewardship, claims, corrections, visibility, consent, credit, or publication
authority. Every instance must remain testable and useful on its own.

## Operating sequence

1. Preserve the source's identity and access boundary.
2. Extract scoped observations without inflating authorship or impact.
3. Associate claims with direct, corroborating, contextual, contradictory, or
   private support.
4. Record anti-claims, uncertainty, corrections, rights, and consent.
5. Project only what is useful and approved for a particular audience.
6. Leave enough provenance and next action for someone who was not in the room.

The method helps produce [Technical Operations](../capabilities/technical-operations.md)
evidence, but an internal pass does not substitute for collaborator review,
rights and consent decisions, publication approval, or external outcomes.
