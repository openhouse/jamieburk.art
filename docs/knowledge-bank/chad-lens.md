# Professional Legibility Lens

This document records the public-safe editorial logic for making Jamie's work
legible to hiring readers without overstating role, ownership, metrics, or
private evidence.

## Core Rules

- Do not make the reader decode Jamie.
- Make Jamie visible as the actor.
- Say toward what end.
- Use action verbs.
- Translate specialized language.
- Show what became usable.
- Use collective-work language where appropriate.
- Avoid unsupported ownership claims.
- Do not let tool lists make Jamie disappear.
- Do not publish private, unapproved, or exact claims without approval.

## Shame-Free Complexity

Prefer language that treats transition as normal and work-in-formation as real
work. "Emerging" is often stronger than "ambiguous" because it names a field
that has signal, needs structure, and deserves care.

Useful public wording:

> Jamie helps emerging, stakeholder-heavy work become usable systems:
> requirements, workflows, documentation, decision trails, launch support,
> onboarding, and durable handoffs.

Internal principle:

> Structure grows out of the material you are working with.

## Translation Table

| Avoid when it blurs role | Prefer when true |
| --- | --- |
| under-structured | emerging, loosely defined, early-stage, resource-constrained, complex |
| tracking | structured, synthesized, maintained, coordinated, surfaced, stewarded |
| lightweight | practical, low-overhead, easy-to-adopt |
| data | open-data workflows, dataset documentation, source maps, public guidance, analytics, data-product requirements |
| maintainers | community platform operators, calendar editors, local stewards |
| AI-ready | human-reviewed AI-assisted workflows, source-backed documentation, reviewable AI support |

## Reader Test

Every strengthened sentence should answer:

- What did Jamie make clearer or more usable?
- Who could use it after the work?
- What public-safe evidence supports it?
- What private boundary remains protected?
