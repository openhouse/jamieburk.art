## What a passing eval means

A passing blind-spot eval means the gap is named and governed. It has an honest
baseline, required evidence, a stopping rule, anti-gaming constraints, a next
action, and a public-projection boundary.

It does **not** mean the missing evidence has been recovered or the blind spot
has been resolved. In particular, the system cannot synthesize collaborator
testimony, human usability results, job-search outcomes, or publication
permission. An instrumented absence remains an absence.

The controls below sit beside the existing claim, source, population, safety,
agency, and projection evals. They are zero-weight acceptance gates: each must
pass without changing the suite's weighted score.

## Recursive priority order

1. Run the collaborator-corroboration sprint.
2. Run five fresh-human hiring-usability sessions.
3. Normalize two recent paid engagements from requirements through handoff.
4. Classify prominent proof as activity, output, outcome, or impact.
5. Start the private, de-identified job-funnel baseline.
6. Run the three-project visual-evidence pilot.
7. Recompose the homepage and priority case studies from the strengthened bank.

Each pass should select the lowest-evidence control, state one bounded
hypothesis, gather only admissible evidence, rerun deterministic and editorial
checks, and retain the change only if it improves that control without weakening
privacy, collective credit, source scope, or public clarity.
