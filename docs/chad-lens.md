# Chad Lens - Professional Self-Representation Guidelines

Use this as a review checklist for resume-facing and portfolio-facing copy.

## Core Rule

Make the unusual work institutionally legible without losing its purpose,
agency, or dignity.

## Checklist

1. Purpose: have we said toward what end the work existed, and why the system
   mattered?
2. Agency: is Jamie visible as the actor, using an accurate action verb?
3. Legibility: would a public-sector, HR, recruiter, or technical-operations
   reader understand this without decoding insider terms?
4. Precision: if we say data, systems, documentation, or AI, have we named the
   specific work?
5. Contribution: are we using stewardship language where appropriate and
   avoiding inflated ownership claims?
6. Reader burden: can the value be understood on first pass?

- under-structured

- tracking
- data
- AI-ready

- Noting.us
- knowledge graph
- LLM
- maintainers
- builds

## Replace Or Explain

- "under-structured" -> "where the need is real but requirements, workflows,
  ownership, documentation, and handoffs are not yet clear"
- "tracking meetings" -> "synthesizing meetings into decision records, action
  trackers, open questions, and stakeholder next steps"
- "data" -> name the specific work: open-data workflows, dataset documentation,
  public-data framing, data-product requirements, analytics, visualization, or
  data management
- "lightweight" -> "small," "bounded," "practical," or "easy to adopt"
- "maintainers" -> "organizers," "calendar organizers," or "community
  operators," unless the technical audience expects "maintainers"

## Final Test

Would a busy hiring manager understand the work without needing Jamie in the
room to explain it?
