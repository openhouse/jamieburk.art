# Knowledge Wiki Family Closure Evaluation

## Automated Contract

The deterministic suite requires one architecture, all five frozen heads, an
explicit donor ledger, reconciled archive observations, indexed reader paths,
bounded campaign outcomes, continuity states, decision-record fields,
public-safety boundaries, adversarial mutations, review packets, and an exact
candidate fingerprint.

Run:

```bash
npm run wiki:test:family-closure
npm run wiki:eval:family-closure
```

The committed state binds the full `docs/knowledge-wiki/` tree and closure
contract to one content fingerprint. Any change to that scope invalidates the
state until it is reviewed and rebound.

## Human Boundary

Automated success cannot approve Jamie's final voice and content review,
collaborator correction, consent, media rights, hiring-reader comprehension,
production deployment, or indexing. Those gates remain open even at 100/100.

The Knowledge Wiki and portfolio retain selective projection: a mature,
public-safe record may remain off the website because it does not serve the
present audience or composition.

## Hill-Climb Rule

Fix the canonical page, source relationship, boundary, or evaluator defect that
caused a failure. Do not weaken a criterion, overwrite a human gate, or add
unsupported prose merely to satisfy a string check.
