# Hiring acceptance evaluation

This bounded evaluation asks what the exact public portfolio communicates in a
live role context. It does not predict employment, impersonate a named person,
or receive private Wiki evidence.

## Separation

1. The public evaluator receives only public route sources, public role context,
   and public reader profiles.
2. The gap resolver receives the public evaluator report and the public-safe
   Knowledge Wiki.
3. Private application status, contacts, communications, and relationship paths
   are unavailable to both committed reports.

Named profiles are simulated lenses based on cited public context. They are not
the person's actual opinion, participation, endorsement, or hiring decision.

The deterministic baseline proves candidate binding, context binding, coverage
classification, freshness, and privacy boundaries. Fresh human reader studies
remain an open authority gate.

## Named public-context gate

`evals/knowledge-wiki/named-hiring-readers.json` adds a stricter synthetic
application test for the current priority opportunities. Six unique named
public-context readers run one at a time in separate sandboxed tasks; Lisa
Gelobter returns separate decisions for the live OTI Senior Product Manager role
and the expired Technical Operations watch pattern.

The gate is deliberately binary and cannot be averaged: every opportunity-reader
pair must return `I would hire this person for this job`. A failed gate may
identify a portfolio-communication gap, but it must not be repaired by inventing
experience, eligibility, authority, current role status, or a reporting line.

Use `npm run check:named-hiring-evals` to validate the committed contract and
latest result. Use `npm run evals:named-hiring-readers` for the strict release
decision; it exits nonzero until every gate passes.
