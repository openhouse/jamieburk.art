# Content Safety

This site is a public-safe proof surface, not a private archive. Publish summaries, redacted artifacts, representative diagrams, approved public links, and careful collective-work language.

Use `docs/proofs-bank.md` as the public-safe knowledge base for professional
claims. The website should project from that bank for clarity, audience, and
purpose; it should not expose every source, caveat, or protected detail.

## Safer Publishing Patterns

- Use public-safe summaries instead of raw source material.
- Use Representative artifacts when literal artifacts would expose private context.
- Use Known / Open / Protected to explain what is public-safe, what needs review, and what is intentionally omitted.
- Move approval uncertainty into launch blockers, review notes, or private working materials.
- Use contribution language for collective civic, community, and client-adjacent work.

## What Preflight Blocks

- Visible public approval TODOs in shipped app code or public content.
- Placeholder resume files or placeholder resume language.
- Private/draft work items in production mode.
- Committed private/source directories.
- Committed env files other than `.env.example`.
- Obvious credential-looking values.
- Private/proprietary font files.
- Raw transcript artifacts in app or public content.
- Known private local paths in shipped content.

## What Preflight May Warn About

- Safety-policy language in docs.
- Care notes that mention privacy, consent, protected material, legal review, or transcripts.
- Typeface policy references to Trade Gothic, Verlag, Gotham Rounded, or Maria as not shipped.

Docs should invite care. The goal is to publish safely, not to make future writing afraid of naming the risks it is designed to prevent.
