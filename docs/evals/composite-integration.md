# Composite Eval Integration

## Decision

`feature/knowledge-f` extends the `feature/evals-F` spine rather than merging the frozen A-N branches. The composite adds one constitutional layer around the existing launch suite: a frozen contract, exact-candidate fingerprints, graph closure, selective-projection governance, normalized public-safety inspection, adversarial tests, and repeat certification.

The existing application, canonical knowledge-bank records, launch evaluator, and 47 criteria remain authoritative. New work is integrated into those locations. No branch-letter schema, runner, or report format is retained.

## Evaluation Classes

- **Deterministic:** contract shape, IDs, weights, hard gates, candidate fingerprints, graph references, publication decisions, public occurrence closure, and normalized safety scans.
- **Semantic:** Chad, Margaret Morse, Warren Sack, agency, collaboration, and longitudinal-thesis criteria already represented in the launch suite.
- **Browser and visual:** responsive behavior, clipping, overlap, navigation, route health, and resume delivery remain required observations.
- **Human:** independent comprehension, collaborator confirmation, rights and consent, exact-SHA production approval, deployment, and postdeploy verification remain `manual-required` until actually performed.

## Certification Boundary

`npm run evals:launch` evaluates the current working candidate and reports its identity, including dirty state. `npm run evals:certify` is stricter: it rejects a dirty worktree, runs the full suite twice, and requires the exact candidate, contract, material inputs, evaluator, and public registry to remain unchanged across both passing runs.

Automated repeat certification is not the independent holdout. It is not Jamie's production approval. It does not deploy the site.
