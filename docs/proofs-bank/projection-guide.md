# Projection Guide

The proofs bank is deliberately broader than the website. Use this guide to
decide which claims belong on which surface.

Before projecting a claim, check:

- the claim status in `claims.md`;
- the source boundary in `sources.md`;
- the page audience and purpose.

## Homepage

Use claims that answer quickly:

- What does Jamie do?
- What is the scale of the proof?
- Why is this credible for technical project management, product operations,
  implementation, and documentation work?

Best claim IDs:

- `CORE-002`
- `CORE-003`
- `HJE-001`
- `NAC-006`
- `CRS-001`
- `WOW-003`
- `WOW-004`
- `SD-002`
- `SD-003`

Avoid:

- long tool lists;
- unresolved citation claims;
- granular archive details;
- legal/policy nuance that requires too much setup.

## Work Index

Use the work index to show portfolio breadth. Each card should answer:

- What was unclear?
- What became usable?
- Why does this matter for the role?

Best claim types:

- project summaries;
- role-fit language;
- bounded metrics;
- public-safety status.

## Case Study Pages

Use case pages for nuance. They can carry:

- exact aggregate counts;
- source-boundary notes;
- Known / Open / Protected sections;
- collaboration language;
- "what this does not claim" language.

- `NAC-001`
- `NAC-003`
- `NAC-005`
- `NAC-006`

- `CRS-003`

- `CRS-007`

- `STM-001`

## Colophon

Use the colophon to explain the method:

- public-safe proof bank;
- selected projection into website copy;
- no private archive browsing;
- no invasive tracking;
- staging first, production only after review.
