# Proofs Bank

This proofs bank is the public-safe knowledge base for Jamie Burkart's
professional accomplishments. The website is a projection from this bank,
edited for audience, clarity, and purpose.

The repo is public. Do not put anything here that would be unsafe, unfair, or
embarrassing if it appeared in a newspaper.

## Purpose

- Keep public claims defensible.
- Keep private source material out of the repo.
- Give reviewers a single place to check claim strength, evidence class,
  projection surface, and guardrails.
- Make Jamie legible as a Technical Project Manager - Product Operations &
  Implementation lead who turns under-structured work into usable systems for
  complex public-facing teams.

## How To Use

1. Start in `claims.md` before strengthening any website or resume-facing claim.
2. Check `sources.md` for the evidence class and public/private boundary.
3. Use `projection-guide.md` to decide whether a claim belongs on the homepage,
   resume page, work cards, case studies, or lab page.
4. Record exact public release wording in `../claim-register.md`.
5. Omit claims from public pages when status is `Pending`, `Private`, or too
   context-heavy for the intended reader.

## Claim Status

- `Ready`: safe enough for public projection using the approved wording.
- `Careful`: usable only with the guardrail and contribution language shown.
- `Pending`: do not publish yet; needs Jamie, collaborator, citation, or artifact
  approval.
- `Private`: may inform internal judgment, but must not be published.

## Evidence Classes

- `Approved resume`
- `Public source`
- `Public-safe archive summary`
- `Firsthand / collaborator context`
- `Jamie approval pending`
- `Collaborator approval pending`

## Projection Rule

The site should not mirror every claim. It should select the smallest set of
strong, audience-relevant claims that makes Jamie legible without overexposing
private source layers.

## Public-Safety Rule

Do not publish private emails, raw transcripts, private coalition notes,
legal-review materials, private correspondence, client-private materials,
internal analytics, private contact lists, stakeholder lists, raw community
records, private fonts, API keys, credentials, `.env` files other than
`.env.example`, unapproved screenshots, unapproved photos, unapproved quotes, or
unapproved collaborator names.
