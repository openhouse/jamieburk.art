# Proofs Bank

This proofs bank is the public-safe knowledge base for Jamie Burkart's
professional accomplishments. The website is a projection from this bank,
edited for audience, clarity, and purpose.

The repo is public. Do not put anything here that would be unsafe, unfair, or
embarrassing if it appeared in a newspaper.

## Purpose

The proofs bank exists to:

- preserve strong, defensible professional claims;
- keep public site copy grounded in evidence;
- separate verified scope from open questions;
- make future edits easier to audit;
- prevent both overstatement and understatement.

The website does not need to show every claim. It should select the claims that
best serve the reader in that context.

## How To Use

1. Start with `claims.md`.
2. Check `sources.md` for the public-safe evidence basis and boundary.
3. Choose the claim that fits the audience and page purpose.
4. Use the `Public wording` field as the default language.
5. Respect the `Guardrail` field when shortening or adapting the claim.
6. If a page needs a new claim, add it to the bank before adding it to app copy.

## Claim Status

- `Ready`: strong enough for public site copy.
- `Careful`: usable publicly only with the guardrail stated in the record.
- `Pending`: do not use publicly until the missing approval or citation is
  resolved.
- `Private`: source material exists, but the claim should not be published.

## Evidence Classes

- `Approved resume`: supported by the public resume PDF or public profile copy
  Jamie has approved for professional use.
- `Public source`: supported by public journalism, public websites, public
  records, or public project pages.
- `Public-safe archive summary`: supported by aggregate analysis of private or
  local records without publishing the records themselves.
- `Firsthand / collaborator context`: known from Jamie or collaborators, but
  still needs approval, citation, or careful contribution language.

## Projection Rule

The site should project from this bank, not mirror it.

For hiring pages, prefer role-fit claims: requirements, workflow mapping,
documentation architecture, source-backed memory, implementation support,
quality assurance, user acceptance testing, stakeholder updates, and handoffs.

For case studies, prefer project-specific claims: what was unclear, what became
usable, what Jamie did, and what boundary remains protected.

For homepage proof, prefer compact claims that a busy reader can understand in
one pass.

## Public-Safety Rule

Do not publish:

- private correspondence;
- raw transcripts;
- raw community records;
- private coalition notes;
- legal-review materials;
- personal contact lists;
- customer, user, vendor, stakeholder, or guest records;
- credentials or account/security records;
- private financial, property, health, or family details;
- unapproved photos, screenshots, quotes, or collaborator names.

If a private archive supports a public claim, describe the aggregate result or
public-safe pattern. Do not describe the private record inventory in unnecessary
detail.
