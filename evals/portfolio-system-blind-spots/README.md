# Portfolio System Blind-Spot Evals

This suite tests whether the portfolio process can notice and govern the risks
created by its own success: evidence density without reader validation,
partially recovered inquiry accumulation, collective-to-individual attribution
drift, platform-shaped visibility, additive composition, mosaic privacy,
self-evaluation, and indefinite polishing.

Run:

```bash
npm run evals:blind-spots
```

After intentionally changing rendered portfolio prose, regenerate the
content-addressed route inventory and public-surface receipts before judging:

```bash
npm run evals:blind-spots:refresh
```

A pass means the controls are explicit, testable, calibrated, and actionable.
It does not mean recruiters understood the site, collaborators approved every
claim, the archive is complete, or a job-search outcome occurred. Those states
require separate external evidence.

## Artifacts

- `control-state.json` binds every blind spot to a signal, trigger, owner,
  decision rule, next test, and evidence-return path.
- `composition-manifest.json` governs audience, argument, action, claim budget,
  and omission for every public route or route template. Exact claim-key
  inventories decompose rendered route data, metadata, MDX prose, and artifact
  descriptions by sentence and semicolon; canonical `<Claim>` nodes remain one
  governed unit because evidence and boundaries travel with the projection.
- `role-evidence-classifications.json` is an exact-set classification of every
  Knowledge Bank claim whose internal text or projection names Jamie, plus
  every proof claim permitted on a public surface. Adding or removing one
  without classifying its source basis fails the suite.
- Work items declare `authoredRoleProofIds` when page authors paraphrase a
  first-person or mixed-basis proof. The checker requires exact coverage through
  a linked canonical `<Claim>` or an attributed authored-prose guard.
- `control-state.json` derives the full-population archive-pass ledger from
  Knowledge Bank inquiries and requires an invisible-labor balance review for
  every project represented there.
- `mosaic-review-2026-07-15.json` is a dated combination-level safety receipt,
  not a participant, collaborator, legal, or human privacy approval.
- `hill-climb-history.json` records failed internal-control iterations and the
  revisions they prompted without presenting the scores as external evidence.
- `runs/current-run.json` points to the current hill-climb run. Each deciding
  judgment is stored separately and hashed.

Use `npm run evals:blind-spots -- --print-bundle-digest` to print the digest
shared by independent judges. The checker recomputes weighted scores and judge
artifact hashes. A separate orchestration receipt records the observed session,
mode, command surface, and raw artifact digest. This creates an auditable process
trail, not cryptographic proof that repository authors could never alter it.
Judge artifacts and returned external receipts are rejected when their lexical
or resolved paths escape the governed directory, or when any repository-local
path component traverses a symbolic link. Returned public-safe receipts become
part of the bundle judged by later rounds.

Iteration 8 reproduced the same traceability failure across both fresh judge
pairs. The iteration budget was therefore extended from 8 to 12 without
lowering a hard gate, score threshold, criterion minimum, calibration
requirement, regression limit, or the external-outcome boundary.

External reader and field-action receipts are optional only while their
protocols remain planned. Once a protocol advances, the checker requires the
matching public-safe receipt, validates its coarse state, and requires aggregate
learning and a content decision at reviewed or learned states. Reader receipts
preserve the digest of the surface actually tested and separately record the
post-decision surface. A failed or concerning one-reader Fair Rent result
requires a second public-safe follow-up receipt before page-specific revision.
A repository change cannot satisfy an external action.
