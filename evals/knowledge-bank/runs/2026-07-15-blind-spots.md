# Seven Blind-Spot Evals - 2026-07-15

## Cycle 1: Baseline

The baseline found seven distinct weaknesses: outputs and outcomes were mixed;
exact-role corroboration had no register; hiring comprehension had no external
protocol; the current offer was broad; artifact cards could be read as visual
proof; survivorship bias was implicit; and launch checklists did not distinguish
automation from human approval.

## Cycle 2: Intervention

Added case-study outcome fields, a present-tense About-page offer, five research
and governance registers, an external hiring-review protocol and honest empty
ledger, a release-state ledger, and seven independently runnable evals.

## Passing Semantics

Each deterministic criterion requires 100/100. For human-dependent blind spots,
100/100 means `governed-open`: absence is explicit, boundaries are enforced,
and next actions exist. It does not mean that human evidence has been obtained.

## Remaining Human Work

- Run five no-coaching hiring-reader sessions.
- Invite collaborator correction and corroboration for exact-role claims.
- Curate and approve real visual proof.
- Review the exact production candidate and explicitly authorize release.

## Verification Result

After one evaluator-hardening correction for prose whitespace and one recursive
governance correction restoring the older command inventory, all seven new
criteria scored 100/100. `npm run check`, `npm run preflight:staging`, and `npm
run preflight:production` passed on July 15, 2026. Production remains blocked by
the human gates above.
