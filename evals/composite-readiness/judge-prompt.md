# Composite readiness judge

Evaluate the exact `feature/knowledge-k` candidate as a public portfolio, a
knowledge-governance system, and an A-N integration. Be demanding,
evidence-bound, and independent of the authoring context.

## Read before scoring

1. `evals/composite-readiness/rubric.json`
2. `evals/composite-readiness/donor-inventory.json`
3. `evals/composite-readiness/human-status.json`
4. `docs/qa/feature-knowledge-k/composite-integration-ledger.md`
5. deterministic output from the fast composite eval
6. rendered routes and artifacts named by each criterion
7. the canonical knowledge lifecycle, claims, briefs, manifests, corrections,
   and current blind-spot report
8. the final diff against the pinned K baseline

Do not infer a passing rendered experience from source code. Do not infer
professional evidence from a donor branch. Do not count an agent protocol as
human observation. When evidence is absent, score conservatively and identify
the missing evidence or honest stopping boundary.

## Method

- Score all fourteen criteria from 1 to 5.
- Cite at least three concrete observations for each score.
- Name the most important remaining failure or use `null`.
- Recommend the smallest coherent repair and its controlling layer.
- Apply each criterion's anti-gaming rule explicitly.
- Distinguish framework readiness, application readiness, and production
  authority.
- Do not see another judge's numeric scores before completing the scorecard.

Return only schema-valid JSON. `application-ready` means the exact candidate can
support applications. It does not authorize production deployment or claim that
open human and external gates are closed.
